## 7. Round 4: Runtime Crash & Data-Correctness Sweep (✅ Done)

Triggered by a hard crash on a real load
(`AttributeError: 'NoneType' object has no attribute 'get'`, `app.py:72`,
2026 Australian GP Race). The reported error was a *symptom*; the audit
traced it to a masked exception, then swept the whole pipeline against
live FastF1 3.8.3 / Streamlit 1.59 / pandas 2.3 data.

### 7.1 Crashes

| # | File | Issue | Fix |
|---|------|-------|-----|
| 7.1.1 | `data/fastf1_adapter.py` | **Root cause.** `get_location()` called `.add_distance()` on `get_pos_data()`. Position data has no Speed channel, so FastF1 raises `ValueError: Telemetry does not contain required channels 'Time' and 'Speed'` — killing *every* FastF1 session load. | Location now comes from the merged `get_telemetry()` (which already carries X/Y/Z **and** Distance). Raw-position fallback derives distance from GPS arc length (÷10: coordinates are 1/10 m). |
| 7.1.2 | `app.py:66-72` | The real error was swallowed: `st.error(...)` then `st.stop()` — but `st.stop()` is a **no-op in bare mode**, so execution continued with `session_data = None` and crashed 6 lines later with a misleading `AttributeError`. | Load moved into `load_session_data()`, which re-raises after `st.stop()` and can never return `None`. |
| 7.1.3 | `app.py` | `python app.py` silently degrades (widgets return defaults, no session state). | `require_streamlit_runtime()` exits 2 with instructions to use `streamlit run app.py`. |
| 7.1.4 | `data/source_manager.py` | `_load_livef1_session()` did `range(len(df)) * 10` — a `TypeError`, latent on every LiveF1 load without a Distance column. | `np.arange(len(df)) * 10`; channel selection filtered to available columns. |
| 7.1.5 | `data/live_adapter.py` | `decode_zipped("")` raised `IndexError` on `text[0]`. | Explicit `ValueError` for empty payloads. |

### 7.2 Data correctness

| # | Issue | Fix |
|---|-------|-----|
| 7.2.1 | **Pit-out markers never rendered.** `get_laps()` looked for `IsPitOutLap`/`PitOutLap`; FastF1 has neither — it exposes `PitOutTime`. The column was silently dropped, so the lap chart's diamond markers were dead code. | `IsPitOutLap` derived from `PitOutTime.notna()` (32 pit-out laps now flagged in the 2026 Australian GP). |
| 7.2.2 | **Meaningless comparison axis + 1.05 M chart points.** `Distance` accumulates over all laps (302 km for a race), so "same X" was not the same corner, and 20 drivers × 60 k points hung the browser. | New **telemetry scope**: default `fastest` (each driver's fastest lap, 0 → lap length, **20,903 points — 50× fewer**); `session` still available. Surfaced as a UI radio and threaded through `get_session_data(telemetry_scope=...)`. |
| 7.2.3 | **3,691 fake gear values.** Linear interpolation of `nGear` produced fractional gears, then `.astype(str)` made each one its own chart category. | Coded channels (`nGear`, `DRS`, `Brake`) resample **nearest-neighbour**; only Speed/Throttle/RPM interpolate. Gear labels rounded to whole numbers; Gear axis pinned to `GEAR_CATEGORIES` (`N`, `1`..`8`). |
| 7.2.4 | Stint counters rendered as "Laps: 12.0" (groupby leaves floats). | `Stint`/`LapStart`/`LapEnd`/`LapCount` cast to `Int64`. |
| 7.2.5 | "Pre-Season Testing" appeared **twice** in the GP dropdown and has no Race session. | `get_available_sessions()` drops `EventFormat == 'testing'` (falls back to `RoundNumber > 0`). |
| 7.2.6 | `build_driver_color_map()` raised `TypeError` on a NaN `TeamName` (`float[:3]`). | NA-safe `_first_present()` helper; rows with no identifier are skipped. |
| 7.2.7 | `MetricsStore.update_laps()` raised `KeyError` when laps had no `Driver` column. | Falls back to `DriverAcronym`, then to `"unknown"`. |
| 7.2.8 | Track map was distorted by the container's aspect ratio. | `yaxis` pinned with `scaleanchor="x"`. |

### 7.3 Caching, performance & config

| # | Issue | Fix |
|---|-------|-----|
| 7.3.1 | **The runtime cache never cached anything.** `runtime_cache.begin_session()` ran at the top of `main()`, and Streamlit re-executes the script on *every* interaction — so the cache was wiped on each rerun and every click re-downloaded the session. | Guarded behind `st.session_state["_runtime_cache_started"]`, so it resets once per app session as intended. |
| 7.3.2 | `_is_race_weekend()` (Jolpica) and `get_available_sessions()` (FastF1 schedule) hit the network on every rerun. | `@st.cache_data` with 15 min / 60 min TTLs. |
| 7.3.3 | Session load called `get_telemetry()` **and** `get_location()` per driver — two expensive car/position merges. | `get_driver_frames()` does one merge and returns both; drivers with no laps are dropped instead of yielding empty frames. |
| 7.3.4 | `config.fastf1_cache_dir` / `config.replay_dir` were never read, so the documented `FASTF1_CACHE_DIR` / `REPLAY_DIR` `.env` settings did nothing (only `load_dotenv()` had been wired in 1.13). | `DataSourceManager(cache_dir=..., replay_dir=...)` defaults to the config values. |

| # | Issue | Fix |
|---|-------|-----|

- All `DeprecationWarning`s under pytest originate in FastF1/pandas internals, not this project (verified by promoting them to errors across the full pipeline).

### M1 — Timing tower semantics

- **DASH-01** — The tower classifies by session type: races and sprints order by `session.results.Position` (falling back to the last lap's `Position`), with Gap/Interval as race time behind the leader and the car ahead, or `+N LAP(S)` once lapped; practice and qualifying keep best-lap ordering. This added a `results` table to the unified session dict — **`REPLAY_SCHEMA_VERSION` bumped to 4** (older replays load with an empty one). Verified against the real 2023 Bahrain GP (P1 VER, P2 PER, P3 ALO, gaps within 0.1 s of `results.Time`).
- **DASH-02** — Knock-out styling is now confined to qualifying and sprint qualifying, partitioned by segment (`Q3` / `Eliminated in Q2` / `Eliminated in Q1`) with cut-offs derived from the entry list (22 cars → 10/6/6, 20 → 10/5/5) rather than a hardcoded top ten. A row shows the time from the last segment the driver set one in, while the partition follows the official position — 2023 Bahrain's HUL reached Q3, set no lap, and classifies P10 on a Q2 time. Races and practice no longer dim anyone. The unused `cutoff` argument is gone.
- **DASH-04** — Dominance slices on the track map follow distance instead of point index. New `processing.timing.segment_boundaries(distance, n)` is shared by the timing strips and the map, and `build_track_svg` carries the reference trace's `Distance` (falling back to GPS arc length) through projection. On a trace with 90 % of its samples in the first 10 % of the lap, the first slice used to cover ~1 % of the path; it now covers ~10 %.
- **DASH-05** — The dashboard is now independent of the chart scope: sources supply per-driver fastest-lap frames as `dashboard_telemetry`/`dashboard_location` (**`REPLAY_SCHEMA_VERSION` 5**; stored in a replay only when they differ from the chart frames), and `processing.timing.dashboard_frames()` falls back to the chart frames for sources that cannot. The track outline is resampled at uniform distance to ≤1500 points, so a full-session race SVG drops well under 150 KB.
- **DASH-06** — The ideal lap now sums each sector's best across *all* of a driver's valid laps (deleted and inaccurately-timed laps excluded via FastF1's `Deleted`/`IsAccurate`, which `get_laps` now carries) instead of the sectors of one fastest lap. Rows gained `best_sectors` and `personal_ideal`; `theoretical_best` takes each sector from whoever was quickest anywhere. The map bench reads "Session ideal" and each row's Diff cell carries the driver's own ideal as a tooltip.
- **DASH-03** — Mini-sectors follow the official convention: purple = session best, green = the driver's own best, yellow = slower than their own best (the old "within 2 % of session best" green is gone). `segment_states` now takes several laps per driver — the first is the lap on screen, the rest set the personal best — though the loader still supplies only the fastest lap each, so multi-lap personal bests wait on HIST-08's cached session. Strips and the dominance map are split at the lap's **real** sector boundaries, derived from `Sector{1,2,3}Time` via `sector_boundary_distances`/`micro_sector_marks` instead of assuming sectors end at 1/3 and 2/3 of the lap.
- **DASH-08** — The header flag only reads `Track`-scoped race-control messages for historical sessions, so a sector yellow or a driver's blue flag no longer becomes the track state; a normal session ends on CHEQUERED and an abandoned one on RED, otherwise SESSION ENDED. Live sessions use `TrackStatus` alone and default to green rather than inferring from history.
- **DASH-09** — The header's clock slot is a real session clock: historical sessions show their duration as `H:MM:SS` (from the session time at the last completed lap — `get_laps` now carries `Time`/`LapStartTime`) labelled "Duration", instead of the weather sampling window. Live sessions read `session_info['extrapolated_clock']` under a "Remaining" label; wiring the `ExtrapolatedClock` topic itself is part of the live work.
- **DASH-10** — Status badges say something: historical rows map `results.Status` to FIN / +NL / DNF / DSQ / DNS (verified on the real 2023 Bahrain race, where retirements previously read "CLASSIFIED"), and live rows use the feed's `InPit`/`PitOut`/`Retired`/`Stopped` — carried into the live laps frame, with retirement latched because the feed is lossy — instead of FastF1-only pit timestamps live laps never have. The synthetic in-progress lap row is marked `IsInProgress` so `laps_completed` no longer counts it.
- **DASH-11** — Tyre badges show the tyre's **age** (`TyreLife`, now carried by `get_laps`) rather than the number of laps in the stint, mark a scrubbed set with a dashed ring (not colour alone), and spell out age/condition/stint length in the tooltip. When the laps carry no compound — as live lap frames built from `TimingData` never do — the history falls back to the session's stint table.
- **TEST-06** — No separate change needed: the wrong "fastest to slowest for every session" expectation was replaced while landing DASH-01/DASH-02 (the Q-session test now asserts the official order and the within-Q3 ordering), and the R-session tests it asked for exist as `TestRaceClassificationOnRealSession`, alongside new real-session tests for status badges and scope independence.

### M2 — Live foundation

- **TEST-01** — Replaced guesswork with a recording: `scripts/capture_fixture.py` pulls 13 topics of the real 2023 Bahrain Race from F1's public static archive into `tests/fixtures/live/` (134 KiB gzipped, refreshable), and `tests/test_live_fixture_replay.py` replays them through the real decode/parse path. The real payloads confirm every shape the audit called out — `SessionInfo.Meeting` nested, `Sectors`/`Stints` deltas keyed 0-based, stint updates with no `Compound`, `Position.z` in 1/10 m — and the LIVE-05 defect is held as a strict xfail so it must flip when the fix lands. The capture also surfaced LIVE-14's garage `0,0,0` samples.
- **LIVE-05** — Delta topics are merged into state instead of being buffered as independent records. New `data/live_state.py` holds one dict per topic with a recursive `deep_merge` that honours `_deleted` and treats a dict arriving over a list as an index-addressed delta; `as_list` normalises those back. `SignalRLiveAdapter.handle_message` routes state topics into `LiveState` and keeps only true time series in the bounded buffers, recording lap completions separately so a long race cannot lose its first half. New builders derive the unified dict's tables from state — stints keyed by acronym with a real lap window from `TotalLaps`/`StartLaps`, `DriverList` no longer first-seen-wins, `SessionInfo`/`SessionStatus` read from state. Verified end to end against the recorded 2023 Bahrain messages.
- **LIVE-04** — Sector deltas land on the right sector. `Sectors` is merged as an index-addressed list and flattened to 1-based `Sectors_N_Value` when read, so the feed's 0-based delta for `"1"` updates S2 and leaves S1 alone — the collision livef1's flattening created. `Segments` no longer leak into those columns. The legacy record path, which cannot distinguish the two shapes, is marked as superseded.
- **LIVE-07** — The live buffers are thread-safe: an `RLock` guards every append, trim and read, and `get_buffered_data()`/`recorded_laps()` return copies rather than the live lists the client thread is still trimming. A stress test runs a writer thread against a polling reader and asserts the reader never sees records out of order.
- **LIVE-01 / LIVE-08** — Marked blocked (`- [~]`), not attempted: both need the SignalR Core client, whose acceptance is a smoke test against a *running* session, and LIVE-08's fix is written entirely against that client's API. The groundwork they will use — merged state (LIVE-05), the `handle_message` ingest entry point, thread-safe buffers (LIVE-07) and recorded fixtures (TEST-01) — is in place.
- **LIVE-09** — One live adapter per *process* instead of per browser tab: `data/live_service.get_live_adapter()` is a lock-guarded module singleton (chosen over `@st.cache_resource` so scripts and tests can reach it without a Streamlit runtime), and `DataSourceManager` uses it unless handed an explicit `live_adapter`. Two AppTest sessions now share one adapter and see each other's data. `tests/conftest.py` resets the singleton between tests so process-wide state cannot leak.
- **LIVE-02** — Without an F1TV token the live view no longer shows nothing: `AUTH_TOPICS` names the subscription-gated topics, `subscribed_topics()` drops them unless `F1TV_SUBSCRIPTION_TOKEN` is set, and `render_live_dashboard` renders timing, tyres, race control and weather regardless, with a banner explaining what needs a token. Replaying the recorded messages through the view also caught a live-only crash — `WeatherData` values arrive as strings and the weather panel formatted them with `:g`.
- **LIVE-10** — The timing dashboard is rendered inside the auto-refreshing live fragment, from each polled snapshot, instead of once outside it from the empty dict a live session starts with — so the header, tower, sector cards and map show live data rather than "No timing data". The duplicate plain "Timing" dataframe tab is gone, since the dashboard *is* the timing view.
- **LIVE-14** — `parse_position_data` drops samples where `Status != "OnTrack"` and exact-zero `X/Y/Z` triples (the garage placeholder), so live trails no longer run a straight line through the origin and distance no longer jumps by a circuit's width on every pit stop. The recorded fixture contains real garage samples, so the filter is tested against them rather than against a synthetic guess.
- **LIVE-15** — "Live session detected" now means one actually is: `live_session_now()` matches the clock against the event schedule's own `SessionNDateUtc` plus a per-session-type duration (15 min lead-in, 30 min run-out) instead of asking whether race day is within ±72 h — which was true from Thursday to the following Wednesday. `Auto` no longer switches silently and hides the historical selectors: it says a session is running and offers a **Go live** button. `JolpicaAdapter.is_race_weekend` remains as the coarse calendar check it always was, documented as not a live test.
- **LIVE-11** — The live poll fits inside its refresh interval: whole-column `pd.to_numeric` replaced one call per record per channel (180 k calls at buffer cap), timestamps are parsed once per frame instead of once per driver, and a change token (state version + lap count + a monotonic ingest counter) lets an unchanged tick reuse the previous snapshot. Full-grid snapshot cost went 1.80 s (audit) → 311 ms (after LIVE-05) → under the 150 ms budget. Lap history is already outside the capped telemetry buffer, so lap 1 survives a full race — now covered by a retention test.
- **LIVE-13** — Live telemetry is segmented into laps: completions record the message timestamp, and each driver's telemetry and GPS trail are sliced to their last completed lap, so Distance runs 0 → lap length and two drivers can actually be overlaid. `session_info` reports `telemetry_scope` (`lap` or `session`), the lap each trace shows and each driver's current lap; without completions it falls back to the running tail. `scripts/capture_fixture.py` now samples a session-time window rather than a message offset, so the recorded topics cover the same period (the old offset landed `TimingData` before any lap had been completed).
- **LIVE-12** — The live controls are reachable (they sat after `main()`'s unconditional `return`) and "Save Raw Stream" actually records: `data/live_recorder.py` writes `subscribe.json` plus append-only `live.jsonl` of `[topic, data, timestamp]` — undercut-f1's format — and `replay_recording()` feeds it back through the same `handle_message` the live client uses, so a replay rebuilds exactly the state the session ended in (asserted against the recorded fixture, torn final line included). Saving a live session used to write the empty dict it starts from.
- **LIVE-16** — Removed the dead live code: `start_fastf1_client` (ignored its topics and blocked), `check_live_session_available` (superseded by LIVE-15's `live_session_now`), `process_live_telemetry` (invented an index-based pseudo-distance) and both `__main__` demo blocks. `LapSeries` is no longer subscribed — nothing parsed it and `TimingData.NumberOfLaps` already gives lap progression — while `TimingAppData` is, since it is the tower's tyre source; the other formerly-unparsed topics are merged state since LIVE-05. `clear_buffer` became a real "Clear Buffers" control rather than unused API. A new test enforces the no-unused-public-functions rule for the live modules; it also surfaced the unused Jolpica `*_df` helpers, left to REPO-05.
- **DOC-01** — The docs no longer claim an endpoint the code does not use. `readme.md`, `ARCHITECTURE.md`, the live adapter docstring and `live_smoke.py` now state that live mode runs through LiveF1's **legacy** `/signalr/` hub (F1 moved to `/signalrcore`; LIVE-01), that it may therefore not connect, which topics need `F1TV_SUBSCRIPTION_TOKEN` and which work without one, that the project is unofficial, and that hosting it publicly risks IP blocking. `tests/test_docs_live_claims.py` stops an unqualified `/signalrcore` claim creeping back.

### M3 — Platform & hygiene

- **REPO-02** — Dependency floors now match the code: `streamlit>=1.55,<2` (it calls `width="stretch"` and `@st.fragment`, neither of which exists in the old `>=1.35` floor), `livef1>=1.2.1,<1.3` since patch releases change parsing shapes, plus the previously-undeclared `requests-cache`, `pyarrow` and `signalrcore`. `requirements.lock` pins exact versions (regenerate with `scripts/lock_requirements.py`), CI installs from it and dry-run-checks that it still satisfies the declared floors. Tests assert every requirement has both bounds, that the installed versions satisfy them, and that everything imported is declared.
- **REPO-03** — One Python version story: the floor is 3.11 (what the readme already promised), `black`/`ruff` target `py311` instead of `py312` — the mismatch was why black warned "Python 3.11 cannot parse code formatted for Python 3.12" on the supported floor — and CI runs a `3.11 / 3.12 / 3.13` matrix with `fail-fast: false`. A test keeps the three in sync.
- **REPO-06** — Ruff now selects `B`, `UP`, `SIM`, `I`, `PD`, `NPY`, `PERF`, `RUF`, `S` (bandit) and `DTZ` on top of the previous four. Of the 409 findings, 387 were autofixable modernisation (`Dict`→`dict`, `Optional[X]`→`X | None`, import order); the rest were fixed by hand — UTC-aware `datetime.now()`, `raise ... from e`, `ClassVar` on constant tables, context managers in tests — leaving four justified `noqa`s (the pickle loader pending HIST-02, the recorder's long-lived append handle, an env-var *name* flagged as a secret, and `assert` in tests). The implicit-`Optional` fixes also took mypy from 19 to 11 errors.
- **REPO-07** — `pre-commit` was a dev dependency with no config for it to run. `.pre-commit-config.yaml` now runs the CI gates on staged files — ruff, black, mypy over `processing/` — plus end-of-file/trailing-whitespace fixers and `check-added-large-files` at 512 KB, which is what would have stopped REPO-01's committed virtualenv. Every hook repo is pinned to a revision, and the readme says how to install it.
- **REPO-04** — mypy is clean (21 errors → 0) and enforced in CI. REPO-06's autofixes removed the implicit `Optional` defaults; the rest were genuine — `get_session_data` handed `int | None`/`str | None` to loaders that require concrete values, which now raises a `ValueError` naming what is missing instead of failing later inside FastF1. `no_implicit_optional` is on so a new one fails rather than accumulating, and `processing/*` (pure transforms) additionally carries `check_untyped_defs`.
- **REPO-11** — Degraded paths say why. Every module that swallows exceptions has a `logging.getLogger(__name__)`, and each `except Exception` now logs the exception (or states why it does not) instead of turning an upstream failure into a silent empty frame — so "No weather data" can be told apart from a network error. `LOG_LEVEL` configures `logging.basicConfig` in `app.py`, defaulting to WARNING. A test scans for silent handlers and for modules missing a logger; surfacing the reason *in the UI* is UX-11, still open.
- **REPO-05** — Dead code removed: `ui.layout.format_lap_time` (and `processing.time_utils.format_m_s`, which only it used), the six unused Jolpica `*_df` wrappers, the `config.distance_step`/`cache_ttl_seconds` fields nothing read, and `app.py`'s `sys.path.insert` — `streamlit run` from another directory still works, because Streamlit puts the script's directory on the path itself. `default_year`/`default_gp`/`default_session` stay: HIST-04 made them the real fallback. Jolpica's *query* methods are kept behind a documented allow-list for FEAT-06, guarded by tests that fail if an entry disappears or quietly gains a caller.
- **REPO-08** — Row-wise work removed from the hot paths, with micro-benchmarks in `tests/perf/`. `parse_car_data`/`parse_position_data` convert whole columns instead of calling `pd.to_numeric` per field per record — that is REPO-08's ≥5×, measured in the test against the old implementation. `build_driver_color_map` no longer uses `iterrows`, and the tyre-strategy chart emits one `go.Bar` per **compound** with arrays rather than one trace per stint row (~90 traces for a race). `seconds_series` is genuinely vectorised now (it was a Python loop behind a "vectorised" docstring), but only ~1.3× faster — a scalar `to_seconds` is already cheap — and the test says so rather than asserting a speedup that is not there.
- **HIST-02** — Replays are data, not code. A replay is now a directory holding `meta.json` (schema, plain values, table index) plus one Parquet per table and one per driver for telemetry/location, round-trip tested for the dtypes the contract carries — Timedelta, NaT, nullable `Int64` and categorical, all of which the old `to_dict("records")` pickle lost. Legacy `.pkl` replays still load, but only through `allow_pickle=True`; by default the loader refuses and says why, since a replay is the one artefact people share.
- **HIST-03** — "LiveF1 (Historical)" is no longer offered. Beyond the attribute and column-name mismatches the audit documented, livef1 1.2.1 raises `AttributeError: 'Session' object has no attribute 'name'` when building a Session for 2023 Bahrain (2024 works), so a rewritten adapter could not even be verified against the session the acceptance names. The selector drops the source, `source="livef1"` raises a `NotImplementedError` naming HIST-03 and pointing at `fastf1`, and tests pin livef1's real `Driver` attribute names for whoever writes the adapter later.

### Requested out of order

- **FEAT-04** — Session replay. `processing/replay.py` resamples every driver's position onto one shared clock (2 Hz) from FastF1's `get_pos_data()` — position data only, so it costs far less than a telemetry merge — and the result travels in the session dict as `positions` (**`REPLAY_SCHEMA_VERSION` 6**, so a saved replay can be played back as well). ## Round 7 — replay and UI

- **REPO-14** — `.gitattributes` (`* text=auto eol=lf`, binaries marked) ends the CRLF-vs-LF churn that showed ~55 unchanged files as modified; `_to_delete/` is ignored and the stale lock folder removed. `test_repo_hygiene` pins `eol=lf`.
- **REPLAY-01** — `processing/replay.ReplayClock` (start / lights out / end, JSON-safe) and `replay_clock()`: a race opens at the first non-NaT lap-1 `LapStartTime`, other sessions at `session_start`. Positions pack into a `PositionCube` (`(F, D, 2)` float32) so `positions_at` is an index computation with linear interpolation between frames (under 2 ms on a 22-car x 14 000-frame cube, perf test), and a tidy timeline passed directly gets its cube built once and cached. The timeline no longer bridges silences over 3 s, so a car in the garage is absent rather than gliding down the pit lane. A Q/FP driver whose first lap has a NaT `LapStartTime` is read from raw `pos_data` from the session start (`include_pre_race` does the same for a race's grid). The replay view keeps its cursor per session (`replay_cursor:<session key>`), opens at lights out, has a "Lights out" button, and its clock is race time `H:MM:SS` from lights out.
- **REPLAY-02** — The session dict carries what the replay needs to be time-true (**`REPLAY_SCHEMA_VERSION` 7**): `timing_stream` (FastF1 parses it and discards it; read back through the private `fastf1._api._extended_timing_data` from FastF1's own cache, racing numbers mapped to acronyms, gap strings kept and parsed by the new `time_utils.parse_gap` into seconds / laps-down; any failure logs a warning and yields an empty frame), `track_status` on the session clock, race control gains `SessionTime` (its `Time` is wall-clock), and `session_info` gains `session_start`, `segment_starts` (from `_session_split_times`, element 0 replaced by the session start, one-day sentinels dropped), `total_laps` and `replay_clock`. Schema <= 6 replays load with empty defaults and a derived clock. Checked on the cached 2023 Bahrain GP: 28 475 stream rows / 20 drivers, VER P1 on its last row; qualifying splits `[899.3, 2758.7, 4138.7]`.
- **REPLAY-03** — `processing/replay_model.py` owns time semantics. `tower_series()` builds, per driver and per field, change-point series (position, gap/interval as display strings and seconds, lap, last/best lap with purple/green flag, sector cells, tyre/age/new/stint, pits, status, qualifying partition), so any moment is a binary search; `snapshot_at(t)` returns a unified dict with laps up to `t` plus one `IsInProgress` row per running car (revealed sectors only, tyre unchanged until the car leaves the box), `standings`, empty `results`, and race control / weather / track status / stream clipped to `t`; `events()` lists SC/VSC/red, pit stops, retirements, fastest-lap changes and the flag. Race order comes from the timing stream (a position counts once it has held 0.5 s - the real stream flickers at the start) or, without one, from laps completed and line-crossing order; qualifying ranks by the best lap in the running segment and knocks cars out only once their segment has ended; OUT means no position sample for 5 s, FIN means a crossing after the flag. `build_timing_rows` takes its order, gaps, status and sector cells from `standings` when present and never reads `results` then; the dashboard draws a snapshot with a race-time clock, lap n/N, the flag at `t` and every car on the map without the dominance layer. A property test garbles everything stamped after `t` (and replaces `results`) for 20 random moments and asserts the snapshot is identical. On the cached 2023 Bahrain race the lap-10 top three matches FastF1 (VER, LEC, PER; VER-PER +8.678 vs 8.792 s from the lap times), the end order equals the classification, and a snapshot takes ~55 ms; the qualifying replay ends exactly on the official order, including the NOR/SAR tie on 1:31.652.
- **UI-00** — No emoji anywhere in the interface: every tab, button, heading, weather metric, telemetry sub-tab and caption in `app.py` / `ui/` is plain text per guideline 5.9 (and the Records lines in `metrics_store.summary_lines`). State indicators are words: `TRACK_STATUS` is `{code: (flag state, label)}` drawn through the new `ui.theme.status_chip`, race control shows the flag word, the lap chart says `PIT OUT`. `tests/test_ui_guideline.py` implements the seven checks of guideline 5.12 (emoji, decoration, radii, remote URLs, hex literals, hype copy, hero title / emoji page icon) plus self-tests of its scanners; the ones the code cannot pass yet are strict `xfail`s naming UI-01 (stylesheet, Google Fonts, `st.title`) and UI-05 (hex literals). Tests that asserted on emoji labels now use the new text.
- **UI-01** — Dark, self-contained shell. `.streamlit/config.toml` sets the dark theme on the guideline 5.4 palette (`toolbarMode = "minimal"`, `runOnSave = false`); `st.set_page_config(page_title="F1 Replay", ...)` has no emoji icon, and `st.title` / `st.caption` are gone (the header bar is the title). `ui/theme.py` holds the 5.4 tokens once (old names kept as aliases) and emits them as CSS variables; the stylesheet lost the Google Fonts `@import`, JetBrains Mono, `backdrop-filter`, the teal sector headers and every radius above 4 px, and numbers use `tabular-nums` instead of a monospace face. Titillium Web 600/700 (OFL, latin subset from the fontsource copy of Google Fonts, fetched once and committed with `OFL.txt` under `ui/assets/fonts/`) is embedded by `ui/fonts.font_face_css()` as base64 `@font-face` in the main document; without the files it returns `""` and the system stack takes over. Team-colour pills pick black or white text by WCAG contrast (`theme.text_on`). The map SVG dropped its `xmlns` URL. Guideline checks 2, 3, 4 and 7 now run as real assertions.
- **UI-02** — The session picker is in the sidebar and nothing loads until **Load session** (the one primary button there) is pressed: the committed choice lives in `st.session_state["selection"]`, and the app shows "Choose a session in the sidebar and press Load session." until then. Deliberate deviation from the plan's `st.form`: a form cannot refresh dependent dropdowns (the Grand Prix list follows the season, the session list the weekend format), so the picker is an `@st.fragment` instead - changing a dropdown reruns the sidebar alone and loads nothing, and Load commits and reruns the app. Seasons run back to 2018; a "Recent" list keeps the last five loads as text buttons ("2023 Bahrain – Race"); a load mirrors `year/gp/session` into the URL and a URL with them preselects and loads on first open. Data source and telemetry scope sit in a collapsed "Advanced" expander; "Auto" is gone - a running session is offered by the "Go live" button at the top of the sidebar instead of switching behind the user's back. AppTests (stub manager counting loads) cover: browsing loads nothing, Load loads once, a shared link preselects and loads.
- **UI-03** — Pages instead of one long scroll. `app.main()` selects and loads once, puts the page context (session dict, processed laps/stints/colours, a lazily built telemetry alignment, metrics label) in `st.session_state["page_context"]`, and hands over to `st.navigation(position="top")`; the function pages live in the new `ui/pages.py`: **Replay** (default for historical and saved sessions; the existing replay view until REPLAY-04), **Results** (today's dashboard plus the tyre strategy chart), **Analysis** (Telemetry, Head-to-head, Lap times, Positions, Weather, Race control chosen with `st.segmented_control`, so only that panel is computed), **Records** (the metrics store, with cache statistics under a collapsed "Diagnostics" expander) and **Live** for a live session. The Plotly track map is gone from both the historical and the live view - the SVG map is the one map. Laps/stints/colours are processed once per session instead of on every rerun, and the records are folded in once per session. "Save session for replay" moved to the sidebar. AppTest reaches function pages by setting the page hash to `calc_hash(url_path)` (`AppTest.switch_page` only takes files); the network smoke test now opens the app on a shared link and visits every page.
- **REPLAY-04** — The replay is the main view. A historical or saved session opens on the **Replay** page at lights out, and the page draws the whole dashboard (header, tower, sector cards, map) from `snapshot_at(cursor)`; the tower series and events are built once per session and kept in session state. Transport: Play/Pause, Lights out, -30s/-5s/+5s/+30s, Previous/Next lap (landing 1 s after the leader crosses), a "Jump to" list from `replay_model.events()`, a race-time scrubber with `0:41:07 · Lap 23/57` beside it, speed, and "Final result", which switches to the Results page (a snapshot has no classification by design). All controls are callbacks on the per-session cursor, so the scrubber always follows whichever control moved it. Playback is the server fallback: a fragment redraws the dashboard once a second. The old map-plus-driver-list replay (`order_at`, `lap_at`, `order_html`) is deleted. AppTest reads the header and tower from the `st.html` markup (`get("html")`): lights out shows race time 0:00:00, Lap 1/5 and the grid order, +30 s moves exactly 30 s (clamped), Next lap lands 1 s after the leader's crossing, "Jump to Pit stop - C" shows C IN PIT, Final result renders the Results tower. Checkpoint, checked in headless Edge on the cached 2023 Bahrain GP: lights out shows the grid (VER, PER, LEC, SAI, ...) at 0:00:00 / Lap 1/57 under a green flag; lap 11 shows VER +7.059 over LEC; no horizontal scroll at 1440 px. The browser check found that the SVG track map had **never** reached the screen - `st.html` sanitises inline `<svg>` away - so the map is now embedded as an `<img>` of a standalone SVG (the namespace URL is logged as a guideline 5.13 exception), and the block padding clears the top navigation.
- **UI-04** — The replay screen specification is `layout.md` section 9: regions and sizes (48 px header, 40/60 tower/map, 3-line race control, 36 px controls, 28 px timeline), tower columns for races and for qualifying/practice, row behaviour (30 px, zebra, focus border, 350 ms slide, interval under 1 s highlighted), timeline shading and marker shapes, transport and keyboard map, the flag chip words, the three breakpoints, and motion/accessibility rules. `ui.theme.FLAG_STATES` labels are now the chip words (`GREEN`, `YELLOW`, `SC`, `VSC`, `RED`, `CHEQUERED`; keys unchanged). The player CSS tokens/breakpoints and the 1440×900 / 390×844 screenshots are checked with REPLAY-05.
- **REPLAY-05** — Smooth playback runs in the browser. `processing/replay_payload.build_replay_payload` packs a session into one JSON-safe payload: clock, track outline, every car's position projected with the map's own transform (the geometry moved to the new pure `processing/track_geometry.py`, shared by the SVG map and the payload), quantised to little-endian Int16 and base64-encoded, one change-point series per tower field with display strings from the model (plus a boolean `close` series for intervals under 1 s, which also halved the tower's share of the payload), flags, race control, weather, leader lap marks, events and qualifying segments. Styling (team, flag, tyre colours) is added by `ui/components/replay_player`, a `st.components.v2` component with no build step (`player.html/.css/.js`, vanilla ES module, shadow-root isolated): it decodes the positions once, interpolates cars between frames at the display refresh rate, binary-searches every tower field, slides rows with `translateY` when the order changes, draws the header, race-control ticker, a timeline with SC/VSC/red shading and shape-coded event markers, and supports Space, arrows, Shift+arrows, `[`/`]`, `1`-`8`, `F` (follow) and `L` (labels). It reports its cursor only on pause, on a seek while paused and at the end; a jump chosen in Python bumps a seek token the player follows. `F1_REPLAY_PLAYER=server` keeps REPLAY-04's view. AppTest **does** mount v2 components on 1.59 (`get("bidi_component")`), so the page test asserts the player is mounted under `replay_player:<session key>` with `cursor` defaulting to lights out and the seek token bumping on a jump. `tests/test_replay_payload.py` checks keys/types, strict JSON, positions decoded within 0.1 viewBox units of the map's projection, the payload tower equal to `snapshot_at`'s at 50 random moments (order, gap, interval, status, tyre) and the 4 MB budget for a 22-car two-hour race; the 2023 Bahrain race payload is 2.39 MB. `scripts/preview_replay_player.py` writes a self-contained `replay_preview.html`. Manual checks (headless Edge driven over the DevTools protocol, since Playwright is not installed - the optional e2e test was not added): the preview of the real 2023 Bahrain race plays (16x: the clock advanced 48 s in 3 s and cars moved), no horizontal scroll at 1440×900 or 390×844 (map above tower at 390), and in the running app 8 s of playback produced **no** script reruns (one `script run` DEBUG line for page load and play together). Fixed on the way: the first position sample lands a fraction of a second after lights out, so both lookups now hold the nearest frame within one frame of either end; tower rows are numbered by rank because the stream briefly gives two cars the same position.
- **REPLAY-06** — Qualifying and practice replays. What REPLAY-03 already built is now covered as this item's acceptance: the header runs the segment clock (`Q2 time`), the tower orders by the best valid lap in the running segment (practice: in the session), Q1-eliminated drivers sit under "Eliminated in Q1" while the rest are ordered by Q2 bests, a faster lap mid-Q2 moves its driver up at that lap's `Time`, and a completed session-best / personal-best lap flashes purple / green in the player (`last_flag`). New: a `flying` series (Q/FP only) marks a lap started after leaving the pits until it completes, or until the car enters the pit lane - an in-lap cannot be told from a timed lap any earlier without looking ahead - carried in the payload and drawn in the player as a small triangle after the driver code with a "On a flying lap" title.
- **REPLAY-08** — Old replays and missing streams degrade honestly. Without a timing stream (a schema <= 6 replay, or FastF1 could not provide it) the model uses the timing-line fallback and both views say so: the player shows "Gaps estimated at the timing lines" under its header and the server dashboard adds the same note under the header bar. Without positions the player still opens with the tower, timeline and track outline, and notes "No car positions for this session." Tests load a schema-6-shaped replay (no stream, no track status, no positions, no stored clock) through `DataSourceManager._finalise_replay` and open it in both views.
